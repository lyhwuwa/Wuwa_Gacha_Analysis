# 鸣潮 · 唤取终端

在原有本地 Streamlit 抽卡档案基础上整合概率模拟。保留鸣潮风格界面、手动编辑、Excel/CSV 导入导出和UP成本轨迹。

## 运行

需要 Python 3.10 或更高版本：

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 真实记录与模拟的联动

- **抽卡记录**：每行代表一个金，填写时间（可选）、角色名、是否UP、距离上次出金的抽数。按从早到晚排列；跨期继承的垫抽仍计入对应出金间隔。编辑后点击“应用记录并更新统计”。
- **当前垫抽**：侧边栏补充最后一个金之后尚未出金的投入。支持标记记录起点已经处于大保底。
- **同预算对比**：点击“用我的总抽数对比模拟”，带入记录抽数加当前垫抽，在模拟分布上叠加真实UP数和金数，并显示包含并列的分位区间。
- **继续模拟**：点击“从当前保底状态继续模拟”，自动带入当前垫抽和下次是否必UP；此时模拟预算是未来新增投入。
- **概率模拟**：可设预算、账号数、起始垫抽、大小保底和种子；提供精确期望、分布、百分位、达标率、示例账号和CSV导出。模拟不会修改真实记录。

导入兼容旧列名 `是否UP?` 和 `是UP?`，支持 UTF-8 / GB18030 CSV。Excel 继续使用原来的“抽卡记录”工作表，额外用“统计设置”保存垫抽和起点状态；已有记录时合并导入会保留当前设置。重复导入相同记录不会再次累加；无时间的相同真实行按出现次数保留。日期和记录顺序不会自动重排。

记录仅保存在当前 Streamlit 会话中，关闭会话前请导出 Excel。部署到远程 Streamlit 服务器时，上传文件由该服务器处理；如果希望完全在本机处理，请在本地运行。

## 模型与口径

采用用户提供图片及作者C代码描述的条件出金概率：

| 第n抽 | 此前未出金时，本抽出金概率 |
|---|---|
| 1–65 | 0.008 |
| 66–70 | 0.008 + 0.04 × (n − 65) |
| 71–75 | 0.208 + 0.08 × (n − 70) |
| 76–78 | 0.608 + 0.10 × (n − 75) |
| 79 | 1 |

每金清零垫抽；小保底50%为UP，歪后下一金必UP，出UP后回到小保底。原公式第79抽为1.008，按概率上限1处理。模型不扣珊瑚返还、不计算兑换共鸣链，不代表对游戏实际后台规则的独立验证。

**已完成UP平均成本**包括此前歪的成本，但不计最后未完成的UP周期；**总投入÷UP数**包含所有已投入抽数。**预算÷期望UP数**是大量账号合并后相除，区别于各账号先相除后取平均。起始垫抽和之前歪的成本不计入模拟预算。

默认0垫抽、小保底开局，1700抽的精确期望：

- 金：31.022688306670467
- UP：20.570681093335864
- 预算÷期望UP：82.64189174323143抽
- 长期出金间隔：54.10274378649243抽
- 长期完整UP周期：81.15411567973865抽

精确期望用158状态逐抽递推；随机模拟使用条件CDF反演，跳过未出金抽数但不改变分布。相同 Python/NumPy 环境下，相同种子可复现。分布范围描述账号间波动，不是均值置信区间。

原记录允许的80抽数据会保留，但与79抽模型不一致时暂停联动比较；连续两次非UP金、无效抽数或不完整行会提示。若历史不完整、混入武器/常驻池，或在出金时选择停止记录，同预算分位只能作参考。
